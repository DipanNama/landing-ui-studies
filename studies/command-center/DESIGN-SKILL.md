# Cinematic Keyboard-First Product Landing

Use this skill for launchers, developer tools, command palettes and desktop productivity products that need to feel fast, precise and desirable.

## Core rules

1. Start on near-black, not pure black: `#07080a` with panels between `#0d0f13` and `#191b21`.
2. Use one warm signal accent (coral/red works well) for the brand moment and hero atmosphere. Save other colors for app or data semantics.
3. Put the product interface in the hero. A command palette, code surface, editor, or timeline is stronger than a generic illustration.
4. Make the first display heading very large, centered and tightly tracked. Keep its supporting copy under three lines.
5. Use thin `#24262c` borders, 14-18px radii, soft inset highlights, and deep black shadows to create hardware-like depth.
6. Show keyboard shortcuts as small mono key caps. Keep them secondary and consistent.
7. Alternate open statement sections with contained demo cards. The empty space makes dense product UI feel premium.
8. Write short outcome-led headings. Explain one behavior per card.

## Layout recipe

- Floating nav: max width about 1080px, 68px tall, 17px radius.
- Hero: 800-900px tall with the product window entering below the main CTA.
- Display scale: 64-86px hero, 48-72px editorial statements, 24-32px feature titles.
- Product grid: two columns with a full-width feature after two half-width cards.
- Extension grid: four columns desktop, two columns mobile.
- Mobile: hide nav links, stack CTA buttons and feature cards, retain a real product mockup, and cap the hero heading near 54px.

## Visual generation

Use layered CSS gradients, masks, geometric shapes and authored interface fragments. Never depend on copied brand art. A diagonal repeating gradient plus blur and a radial mask creates a useful cinematic light-field substitute.

## Interaction

- Sticky navigation can retain a blurred background.
- Anchor links should scroll smoothly.
- Product mockups may include hover or focus states, but the default frame must already explain the feature.
- Preserve keyboard accessibility and visible focus styling in production work.

## Avoid

- Bright gradients across every section
- Generic dashboard screenshots unrelated to the headline
- Heavy glass effects that flatten contrast
- Tiny mobile type or desktop layouts simply scaled down
- Copying third-party brand marks, screenshots, icons or exact product text
